# EasyTier 自定义构建

本说明用于在一台 Ubuntu 主机上构建 EasyTier Linux amd64 Core/CLI、Linux GUI、
Android APK 和 Docker 镜像。Windows x64 Core/CLI、GUI 及 NSIS 安装程序由
GitHub Actions 构建。所有产物记录其完整源码提交；脚本不修改 EasyTier 核心源码
或 Cargo 配置。

当前脚本使用的源码入口是 Cargo package `easytier`，生成：

- `easytier-core`
- `easytier-cli`

## 1. Ubuntu 环境准备

以下命令在 Ubuntu 上安装编译所需的系统工具：

```bash
sudo apt update
sudo apt install -y build-essential musl-tools musl-dev protobuf-compiler pkg-config libclang-dev \
  libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libxdo-dev libssl-dev \
  libappindicator3-dev patchelf
```

Docker 请按 Docker 官方文档安装，并确认当前用户有权限执行：

```bash
docker version
docker buildx version
```

本仓库当前本地 Action 固定使用 Node.js `22`、pnpm `10`；本地构建建议使用相同版本。
Linux GUI 还需要桌面构建依赖（已在上述 apt 命令中列出）。

## 2. 安装 Rust

项目当前要求 Rust `1.95`。若尚未安装 Rust，请使用 rustup 安装；随后在
仓库根目录执行：

```bash
rustup toolchain install 1.95
source "$HOME/.cargo/env"
rustup target add x86_64-unknown-linux-musl
protoc --version
```

`protoc` 必须可在 `PATH` 中找到。Cargo 会按 `Cargo.lock` 锁定依赖版本。

## 3. 构建 Linux amd64

```bash
./scripts/build-linux.sh
```

这会以 release 模式为 `x86_64-unknown-linux-musl` 构建，并使用 `jemalloc`。
产物位于：

```text
artifacts/linux-amd64/
├── easytier-core
├── easytier-cli
├── SOURCE_COMMIT.txt
└── VERSION.txt
```

`SOURCE_COMMIT.txt` 是精确源码提交；`VERSION.txt` 记录 package version、Git
描述和 Rust target。

## 4. 构建 Linux GUI 与 Android APK

```bash
./scripts/build-linux-gui.sh
./scripts/build-android.sh
```

Linux GUI 目标为 `x86_64-unknown-linux-gnu`，产物位于
`artifacts/linux-gui-x86_64/`。Android 脚本沿用官方构建目标，生成 aarch64、
armv7、i686 与 x86_64 APK 到 `artifacts/android-apk/`。

Android 首次使用前需要安装 Java 21、Android SDK Build Tools `34.0.0`、
Platform `android-34` 与 NDK `26.0.10792818`，并设置 `ANDROID_HOME`。脚本不会
自动安装这些大型组件。

## 5. Windows x64 由 GitHub Actions 构建

首次使用时，在 Fork 的 **Actions** 页面启用 Actions（如 GitHub 提示 Fork 的
Actions 尚未启用）。随后将
`.github/workflows/build-windows-x64.yml` 提交并推送到 Fork 默认分支；远程
Actions 只有在该文件已存在于远程默认分支时才能运行。

该工作流仅支持手动触发，构建 Windows x64 MSVC Core/CLI、GUI 与 NSIS 安装程序，
并收集 `easytier/third_party/x86_64/` 中所需 DLL/SYS。两个 Artifact 保留 30 天：

```text
easytier-core-windows-x86_64-<short-sha>
easytier-gui-windows-x86_64-<short-sha>
```

Windows Core and GUI artifacts generated by this custom workflow are unsigned custom builds.

网页手动执行：**Actions → Build EasyTier Windows x64 → Run workflow**，在
`source_ref` 填入 branch、tag 或完整 commit SHA。

Ubuntu CLI 方式需要先登录 GitHub CLI：

```bash
gh auth login
```

依次选择 `GitHub.com`、`HTTPS` 和 `Login with a web browser`。登录信息由 GitHub
CLI 管理，脚本不会保存 GitHub Token。随后可触发当前完整提交并下载结果：

```text
./scripts/build-windows-action.sh
```

下载位置为 `artifacts/github-actions/windows-x86_64/<full-sha>/`。历史下载不会被
脚本清理；需要长期保存时请另行归档。

## 6. Docker Hub 登录

在 Docker Hub 的 Account Settings → Personal access tokens 中创建一个具有
Read & Write 权限的访问令牌。不要把令牌写入脚本、README、Git 仓库或 shell
历史文件。需要推送镜像时，先进行交互式登录：

```bash
docker login --username <Docker Hub username>
```

在 Password 提示中粘贴 Docker Hub Personal Access Token。登录状态由 Docker
管理；本仓库脚本不会读取、保存或输出 token。

## 7. 构建 Docker 镜像

先构建 Linux 产物，再指定自己的 Docker Hub 用户名；仓库名可选，默认是
`easytier-custom`：

```bash
./scripts/build-linux.sh
DOCKER_USERNAME=你的DockerHub用户名 ./scripts/build-docker.sh
```

镜像 tag 自动取当前源码的 `git rev-parse --short HEAD`，脚本同时创建：

```text
${DOCKER_USERNAME}/${DOCKER_REPOSITORY:-easytier-custom}:<commit>
${DOCKER_USERNAME}/${DOCKER_REPOSITORY:-easytier-custom}:latest
```

脚本复用仓库已有的 `.github/workflows/Dockerfile`，以 Linux musl 二进制创建
`linux/amd64` Alpine 镜像，并通过 Buildx 的 `--load` 将两个标签加载到本地
Docker daemon。构建脚本不会登录或推送。

## 8. 推送到 Docker Hub

先完成交互式 `docker login`，再单独推送本地已构建的两个标签：

```bash
./scripts/push-docker.sh
```

脚本只使用当前 Docker 登录状态，随后推送 commit 与 `latest` 两个标签。若未
登录或推送失败，脚本会输出重新执行 `docker login` 的提示。

## 9. 一次完成本地构建与发布

```bash
export DOCKER_USERNAME=你的DockerHub用户名
./scripts/build-all.sh
```

该命令会构建 Linux Core/CLI、Linux GUI、Android APK 和本地 Docker 镜像。默认不
触发 GitHub Actions、不登录、不推送，也不需要 token。

如需额外构建并下载 Windows x64 产物，显式使用：

```bash
./scripts/build-all.sh --windows-action
```

如需在构建成功后推送，先完成 `docker login`，再显式使用：

```bash
DOCKER_USERNAME=你的DockerHub用户名 ./scripts/build-all.sh --push
```

两个选项可以组合：

```bash
DOCKER_USERNAME=你的DockerHub用户名 ./scripts/build-all.sh --windows-action --push
```

也可设置可选的镜像仓库名：

```bash
DOCKER_USERNAME=你的DockerHub用户名 DOCKER_REPOSITORY=my-easytier \
  ./scripts/build-all.sh
```

## 10. 运行 Docker 容器

Dockerfile 保留官方的 Alpine、`tini`、健康检查与 `easytier-core` 入口方式。
host network 和 TUN 设备由运行容器时指定，而不是写入镜像：

```bash
docker run --rm \
  --network host \
  --device /dev/net/tun \
  --cap-add NET_ADMIN \
  "${DOCKER_USERNAME}/easytier-custom:latest"
```

## 11. 同步官方 upstream

当前仓库的 `origin` 是你的 Fork。若尚未添加官方远程仓库，可手动执行一次：

```bash
git remote add upstream https://github.com/EasyTier/EasyTier.git
```

后续同步主分支：

```bash
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```

处理冲突并验证构建成功后，再执行最后一条 `git push`。本构建流程不修改 Cargo
文件和 EasyTier 核心源码，因此通常不会增加 upstream 合并冲突。
